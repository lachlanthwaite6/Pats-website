# Data definitions and differences from the original R script

The original workbook and R file are retained privately, unchanged. The importer reproduces the main aggregates while making limitations visible. This is an engineering implementation of supplied logic, not independent validation of the source business model.

- **Customer counts:** retain `Channel == E`, `Suppressed == 0`. Front-book uses the latest demand date; back-book uses each plan's own last unsuppressed report. The mixed-date total is labelled explicitly, with latest-date and base-table totals shown separately. Missing reports remain visible with no report date; their zero contribution does not establish zero active customers. Multiple same-grain E rows are flagged. E_CL rows are excluded as in the original script; meter/customer interpretation still needs domain-owner review.
- **Plan metadata:** do not silently drop unmatched plans. Use catalogue network/type where demand metadata is absent, and retain any remaining Unknown rows. Legacy plans are not judged by new sign-ups. Front-book flags use the supplied 2-sign-up / 15-competitor thresholds, with network case normalisation. A low-signup small market requires review rather than an automatic healthy verdict.
- **Portfolio margin:** sum `Margin$ * Customers` divided by sum `AnnualPrice * Customers` using the SAME valid rows and positive annual prices. Missing/unpriced data is reported; it is not silently included only in the denominator. This is a reference-price model, not an audited realised margin.
- **Back-book statuses:** retain the original exact status names, including exclusions. Headline stake/churn values use the same legacy status scope as the displayed rows. Per-status mean plan margin remains unweighted and is labelled accordingly.
- **Competitors:** counts are events, not proven unique customers. Identification rates use event weights (`n`), rather than treating a grouped row of 20 events as equivalent to one event. Unknown destinations remain in the denominator.
- **Rank model:** same non-overlapping windows, capped at seven days and at the next ranking date. Only windows fully covered by event dates are used. Variable windows are normalised to seven-day rates. Ordinary least squares is calculated offline; mean-response 95% confidence intervals use Student's t. This is association, not price elasticity. The slider is bounded by actual observed average ranks. Explanations reflect the fitted slope rather than hardcoded claims.
- **Acquisition cost:** the original app hardcodes $0. With no spend dataset to substantiate that value, this build displays Not measured.
- **Workbook formulas:** reads saved/cached Excel values. It does not recalculate formulas. Save a fully recalculated workbook before import. Invalid required dates/counts and Excel error markers stop the import. Existing workbook assumptions remain subject to review.

`meta.sourceSha256`, pipeline version and import time identify provenance. API schema validation checks finite numbers, strict allowed fields, length limits, unique plan codes and reconciled within-snapshot customer totals. The quality view exposes discrepancies between source populations; validation does not mean those populations are equivalent.
